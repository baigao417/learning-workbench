# All-in-One 学习工作台：产品方向

## 用户真正得到什么

用户打开一个学习台后，可以在一个有状态的连续工作区内完成：备课、学习、记录、回看、训练和复盘，而不需要反复在播放器、笔记软件、截图工具、AI 对话和知识库之间搬运上下文。

“All-in-One”指连续工作流和状态统一，不是把所有功能永久堆在一张页面上。

## 旧范式天花板

传统流程通常把播放器、课程笔记、个人笔记、截图、知识库和练习分散在多个工具里，导致：

- 学习前需要重复整理；
- 学习中需要切换和搬运上下文；
- 图像和视频语境难以回到原位置；
- 看完课程与实际训练脱节；
- 学习结果无法反过来改善下一次学习。

## 核心机制

一次素材处理，服务多个后续结果：

```text
原始课程
→ 逐字稿/时间戳
→ 预览、线性笔记、思维导图
→ 学习记录和时间锚点
→ 训练任务和结果
→ 知识关系与学习计划更新
```

## 所需底座

第一阶段至少需要以下实体：

- course / chapter / lesson；
- source segment / timestamp；
- preview / linear note / mind map；
- user annotation / friction note；
- screenshot anchor；
- practice task / practice result；
- knowledge point / relation；
- version change / verification receipt。

## 载体判断

第一版采用桌面优先的多区域学习工作区：视频、笔记和结构视图需要在学习时保持可达；播放器和笔记之间必须保留时间锚点；高级知识重组和复盘可以渐进展开，不应阻塞默认学习路径。

## MVP 验收

用一门 5—20 小时的真实课程完成至少一次：

1. 导入材料；
2. 生成逐字稿、预览、详细笔记和思维导图；
3. 在学习页面播放并记录至少一个时间戳/批注；
4. 根据当天内容完成一个训练任务；
5. 保存训练结果和一个真实摩擦；
6. 下一周期只修一个摩擦，并在真实学习中验证。

## 关键指标

- 备课耗时；
- 学习过程中的工具切换次数；
- 找回一个知识点或视频片段的耗时；
- 学习后训练完成率；
- 用户记录中“增量理解”相对于“抄写内容”的比例；
- 第二次接触相似内容时可安全跳过的重复比例；
- 真实学习是否在工具工作之后发生。

## 明确不做

在 MVP 之前不做多学科通用平台、社交/排行榜、复杂推荐、外部 MCP 大规模接入、自动掌握判定、全量课程批处理和未经验证的自动跳课。
